# RA Companion v0.7 Canonical Source Promotion

Status: implementation gate for `refactor/v0.7.0-source-promotion`.

The purpose of this step is to promote the exact, already-shipping v0.6.4 application result into a normal canonical `app/` source tree before any structural refactor or rcheevos implementation begins.

## Invariants

- No deliberate product behavior changes.
- v0.6.4 remains the behavior baseline.
- Official RetroAchievements server progress remains authoritative for completed/locked state.
- Dolphin integration remains read-only.
- Account isolation, offline achievement library, updater behavior, overlay behavior and Windows branding must remain intact.
- The promoted source must build directly without replaying `build-source/`, `build-overrides/` or `hotfixes/`.

## Promotion gate

The promotion workflow must:

1. Reconstruct the trusted legacy baseline and apply every shipping transform through v0.6.4.
2. Freeze that exact transformed application tree before dependency installation/build output can modify it.
3. Run syntax checks, the full regression suite, production build, NSIS packaging, packaged executable icon validation and Microsoft Defender on the transformed tree.
4. Run ClamAV on the transformed installer.
5. In a clean job, unpack the frozen canonical source and repeat the same direct build/regression/package/security checks without using the historical patch stack.
6. Commit `app/` only after both transformed and direct-source validation paths pass.

The historical patch stack stays in git for provenance while this branch is reviewed. Once canonical-source parity is proven and merged, future v0.7 work should build from `app/` directly and the historical reconstruction pipeline can be retired from the active build path.

## Next step after promotion

Only after this gate is green should the structural v0.7 refactor begin: Electron service boundaries, renderer/profile boundaries, then the native `ra-runtime-helper.exe` proof of concept with pinned rcheevos.
