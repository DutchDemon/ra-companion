# v0.7 Rich Presence Presentation Milestone

## Scope

This milestone surfaces the official RetroAchievements Rich Presence text already evaluated locally by the pinned read-only `rcheevos` runtime.

The previous milestone established the native Rich Presence parser/evaluator. This layer makes that evaluated text available to the user in the normal RA Companion snapshot, Current Game experience and overlay.

## Source priority

Visible game context now follows one explicit priority order:

1. **Official local rcheevos Rich Presence** — the authenticated `PatchData.RichPresencePatch`, evaluated against read-only Dolphin memory by the local pinned rcheevos runtime.
2. **RA Companion RAM context fallback** — the existing profile-specific read-only context string when an official local Rich Presence string is not currently available.
3. **RetroAchievements profile Rich Presence fallback** — the existing server profile message as the final fallback.

The renderer records which source actually won, so source labels cannot claim RAM or server context when another source is being displayed.

## Snapshot contract

When the local rcheevos runtime is active for the current game, has a loaded Rich Presence script and is not stale, `getSnapshot()` exposes:

- `presence.message` — evaluated official Rich Presence text;
- `presence.source = 'rcheevos-runtime'`;
- `presence.live = true`;
- `presence.updatedAt` — last local Rich Presence update timestamp;
- `presence.ageMs` — current age of that locally evaluated Rich Presence sample.

If that local source is unavailable, the snapshot falls back to RAM context and then the RetroAchievements profile message.

## Presentation

### Dashboard / Current Game Session

The Current Game Session hero shows the selected live context text. Official local Rich Presence is identified as `RA RICH PRESENCE`.

### Current Game

The existing Current Story Context uses the same selected presence text. Its Context source field now reports the actual selected source:

- `Official RA · rcheevos`
- `Dolphin RAM fallback`
- `RA server profile`
- `Waiting`

### Overlay

The overlay shows the selected Rich Presence/context text in a compact live block. When official local rcheevos Rich Presence is active, an `RA RP` badge is shown. The compact overlay clamps the line to keep the existing small preset usable.

## Authority and safety boundary

This milestone does not change achievement authority or the emulator access model.

`app/electron/main.cjs` still preserves:

```js
const progress = baseProgress;
```

Therefore Completed/Locked continues to come from the RetroAchievements server/Web API.

No `startsession`, gameplay `ping`, `awardachievement`, or `submitlbentry` calls are added. Dolphin memory remains read-only.

## Validation

The milestone includes a permanent UI contract test that checks:

- local rcheevos Rich Presence is the first source;
- RAM is the second source;
- server profile Rich Presence is the final fallback;
- the overlay and Current Game Session presentation hooks exist;
- the displayed source label tracks the source that actually won;
- the new snapshot source is typed;
- `const progress = baseProgress;` remains intact.

CI also runs existing observer/runtime regressions, TypeScript checking, the full app regression suite and the production renderer build.

## Next milestone

With official Rich Presence visible end-to-end, the next presentation layer can consume the already-cached rcheevos measured achievement state for reliable live counters such as `X / Y`, without changing server-authoritative achievement completion.
