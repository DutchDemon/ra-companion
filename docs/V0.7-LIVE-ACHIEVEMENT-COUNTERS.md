# v0.7 Live Achievement Counters

## Goal

Surface reliable live progress for count-based RetroAchievements achievements without making RA Companion an unlock authority.

## Source priority

For the active game, counter presentation uses:

1. **Local rcheevos measured progress** from the already-loaded official achievement definition (`measuredValue`, `measuredTarget`, `measuredText`).
2. **RetroAchievements Web API measured fields** when present on the achievement payload.
3. **Read-only game/RAM counters** from the game profile as a fallback for explicitly supported values such as Poe Souls, Golden Bugs, Tears of Light, Fused Shadows, Mirror Shards, and Game Overs.

No counter is synthesized from guessed chest flags or guessed memory mappings.

## Presentation

Live counter cards are surfaced in:

- Dashboard → Current Game Session
- Current Game → Live Achievement Progress
- Floating gameplay overlay
- Existing current-game achievement rows

The UI shows the counter source so it is clear when progress is coming directly from rcheevos versus a RAM fallback.

## Selection

The session/overlay summary prioritizes unfinished measured achievements that are already in progress or contextually relevant. Zero-value counters are not sprayed across the UI unless the achievement is relevant to the current context.

## Authority boundary

This feature is **observer/display only**.

- `const progress = baseProgress;` remains unchanged.
- Completed/Locked remains RetroAchievements-server authoritative.
- Local rcheevos trigger state is not used to mark achievements completed.
- Dolphin memory remains read-only.
- No `startsession`, gameplay `ping`, `awardachievement`, or `submitlbentry` calls are introduced.

## Chest achievements

This layer can immediately display a chest counter when the official achievement definition itself exposes reliable rcheevos measured progress.

For chest achievements that do not expose measured progress, RA Companion still requires an exact verified chest/Tbox flag mapping before adding a RAM fallback. Those mappings must not be guessed.

## Final validation scope

The release-grade gate validates the clean source diff, native measured-progress path, TypeScript/regression/production build, packaged renderer, pinned rcheevos helper, NSIS validation installer, Microsoft Defender scan, and an independent ClamAV scan.
