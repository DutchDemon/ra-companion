# v0.7 Runtime Auth + Official Game Data

This milestone connects RA Companion's observer-only rcheevos runtime to official RetroAchievements game definitions without reusing the public Web API key as a runtime credential and without starting a second gameplay session.

## Authentication boundary

- The existing username + Web API key remains the normal RA Companion account/progress connection.
- Runtime data requires the same verified account and a separate one-time password exchange through RAPI `login2`.
- The password is never written to disk.
- The returned runtime token is encrypted with Electron `safeStorage` when OS-backed encryption is available.
- If OS-backed encryption is unavailable, the token is kept in memory only for the current app process.
- Changing or disconnecting the verified Web API account clears the runtime token and any loaded observer game.

## Official game-data boundary

Runtime game data is fetched from RetroAchievements RAPI `patch` using the runtime token. The service keeps the official raw achievement `MemAddr` definition intact and passes only core achievements (`Flags == 3`) into the local observer runtime. Unofficial achievements and leaderboards may be represented as metadata, but are not submitted or treated as official completion.

For a supported active GameCube profile, the normal snapshot flow may asynchronously ensure that the matching RA game definitions are loaded and that the observer is attached read-only to the detected Dolphin process. A failed observer sync does not block normal snapshots or replace server progress.

## Observer-only safety boundary

The runtime-data service has no request path for:

- start-session
- gameplay ping
- achievement award/unlock submission
- leaderboard submission

Official Locked/Completed state remains the existing server result (`const progress = baseProgress;`). Local rcheevos states such as active, primed, measured or triggered are observer context only.
