# v0.7 Official Rich Presence Milestone

## Goal

Evaluate the official RetroAchievements Rich Presence script locally through the same pinned read-only `rcheevos` runtime that already evaluates achievement conditions.

This milestone does not invent game-specific Rich Presence rules. The source is the official `PatchData.RichPresencePatch` returned by the RetroAchievements runtime API.

## Data path

1. RA Companion authenticates to the RetroAchievements runtime API with the existing encrypted runtime token.
2. The `patch` response is normalized by `ra-runtime-data-service.cjs`.
3. `PatchData.RichPresencePatch` is forwarded unchanged to `observer-runtime-service.cjs` as `richPresenceScript`.
4. The observer sends the script to the native helper through `activateRichPresence`.
5. The helper calls `rc_runtime_activate_richpresence` from pinned `rcheevos v12.5.0`.
6. Every existing observer frame still calls `rc_runtime_do_frame` exactly once.
7. The same `evaluateFrame` response now also contains the current output of `rc_runtime_get_richpresence`.
8. The observer live cache stores the evaluated string and its update timestamp alongside measured achievement state.

There is no second 60 Hz Rich Presence IPC loop.

## Teardown and isolation

A new `clearRuntime` helper command destroys and reinitializes the local `rc_runtime_t` while leaving the read-only Dolphin mapping lifecycle separate.

RA Companion invokes this during observer teardown. This guarantees that a game/account switch clears:

- active achievement definitions;
- shared rcheevos memrefs;
- active Rich Presence script/state;
- cached live Rich Presence text.

The observer still keeps its generation guard, so an in-flight frame from a previous game cannot repopulate the new session cache after teardown.

## Authority boundary

Rich Presence evaluation is local display context only.

It does not alter the existing completion model:

- Completed/Locked remains server-authoritative.
- No local achievement event becomes an unlock.
- No `startsession` call is added.
- No gameplay `ping` call is added.
- No `awardachievement` call is added.
- No `submitlbentry` call is added.

The helper remains read-only toward Dolphin memory.

## Native protocol additions

The helper now advertises `richPresenceEvaluation: true` and supports:

- `activateRichPresence` — parse/activate an official rcheevos script;
- `richPresence` — evaluate the active script against attached Dolphin memory;
- `clearRuntime` — atomically clear achievement and Rich Presence runtime state;
- `evaluateFrame.richPresence` — current evaluated text returned with the existing frame response.

The native `--self-test` now includes `richPresenceRuntime`.

## Validation

Automated coverage checks:

- official `RichPresencePatch` forwarding;
- rcheevos Rich Presence parser activation;
- live Rich Presence caching on observer frames;
- measured achievement state and Rich Presence coexisting in the same runtime;
- parse-failure rollback;
- helper-restart invalidation;
- game mismatch blocking;
- `clearRuntime` removing both achievements and Rich Presence;
- no RA submission/session endpoints being introduced;
- production app regression/type/build checks;
- pinned `rcheevos v12.5.0` native build and Node-to-native integration.

## Next milestone

Expose the observer's evaluated official Rich Presence string through the public snapshot/runtime status and make it the preferred Current Game Session / overlay presence source, with the existing game-profile RAM text retained only as a fallback when official Rich Presence is unavailable.
