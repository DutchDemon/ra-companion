# v0.7 Live Runtime Milestone

## Scope

This milestone adds the first production continuous evaluation clock for the read-only rcheevos observer runtime.

It is intentionally a foundation layer. Rich Presence evaluation and UI consumption are separate follow-up work built on top of this clock.

## Runtime behavior

When an official RA game definition set is sealed and Dolphin is attached to the expected GameCube title, the observer runtime can now:

- start a continuous local evaluation clock;
- target approximately 60 Hz (`16 ms`) without overlapping frame requests;
- run `rc_runtime_do_frame` through the existing pinned native helper;
- seed and maintain a cache of local achievement runtime states;
- expose measured value, measured target and measured display text from rcheevos;
- retain a bounded list of recent local runtime events;
- expose target/effective evaluation rate and last-frame timing diagnostics;
- retry transient sampling failures without creating concurrent evaluations;
- invalidate the clock when the native helper generation changes;
- stop and clear all cached live state when the observer game is cleared.

A generation guard prevents an in-flight sample from an old game/account session from repopulating the live cache after a clear or reload.

## Authority boundary

This remains an observer-only layer.

The local runtime does **not** become the source of truth for achievement completion. `app/electron/main.cjs` continues to preserve:

```js
const progress = baseProgress;
```

Therefore Completed/Locked state continues to come from the official RetroAchievements Web API/server state.

This milestone does not add or call:

- `startsession`
- gameplay `ping`
- `awardachievement`
- `submitlbentry`

No achievement or leaderboard result is submitted by the live observer clock.

## Validation strategy

The service tests cover:

- successful definition loading and on-demand evaluation;
- initial live-state seeding for all loaded achievements;
- measured value/target/text caching;
- bounded recent event caching;
- continuous timer scheduling and rescheduling;
- manual stop behavior;
- clear-game cache teardown;
- wrong-game blocking;
- helper-restart invalidation;
- rollback after definition parse failure;
- duplicate definition rejection before native activation.

CI additionally validates the existing app regression suite, production build and pinned `rcheevos v12.5.0` native observer integration.

## Next milestone

Use this live evaluation clock for official rcheevos Rich Presence evaluation, then expose the evaluated presence and selected measured/runtime state to the RA Companion snapshot/overlay without changing the server-authoritative completion model.
